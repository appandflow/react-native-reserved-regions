# react-native-reserved-regions 0.1.0-alpha.1

Candidate notes. This version has not been published; preparing these notes does
not create a release tag or change npm dist-tags.

## API and example

- A Fabric provider and hook report active display divisions and occlusions in
  logical points relative to the provider. Line-shaped divisions are preserved.
- `useReservedRegionsReady()` distinguishes the initial pending state from a
  completed measurement with no regions. `useReservedRegions()` always returns an
  array. Readiness remains true for the provider lifetime.
- The public tagged union distinguishes `division` from `occlusion`. Divisions
  expose `occludesContent`; iOS divisions currently assume content stays visible.
- UIKit reserved-region queries use typed iOS 27.1 declarations behind SDK compile
  guards and runtime availability checks. Older-SDK builds compile out observation
  even when subsequently installed on a newer device.
- Android maps separating or fully occluding WindowManager folding features to
  divisions and display cutout rectangles to occlusions. Frames are translated
  into provider coordinates and clipped to provider bounds.
- The example compares full-screen, inset, and content-box providers with
  `react-native-safe-area-context` insets. Documentation source, pnpm/Ox/TypeScript
  tooling, and a validated release workflow are included in the repository.

## Fixes

- Android initial measurements run after Fabric mounting, before the event beat.
  This avoids the observed Pending frame on the tested Android 16 emulators.
- Android cutout geometry uses `DisplayCutout` bounding rectangles rather than
  treating a full status-bar rectangle as a physical cutout.

## Compatibility and migration

The package requires React Native's New Architecture. The example uses
`0.88.0-rc.1`; a broader supported React Native range has not been established.
iOS observations require both the iOS 27.1 SDK and runtime. Android requires
API 24 or later, with API 28 for cutouts and device support for folding features.

The provider reports geometry. It does not reposition content, replace safe area
or keyboard insets, or expose hinge sensor angles. Hinge posture and angles live
in the separate
[react-native-hinges](https://github.com/appandflow/react-native-hinges) package.
iOS frames may include interaction margins and are forwarded from UIKit without
an additional clipping pass; Android clips its native rectangles to the provider.

After upgrading the package, install iOS pods and rebuild the native app.
A JavaScript-only reload cannot replace the native implementation.

## Verification

The implementation at `1f0d1232ae75dfecfa605c55d51818438185a279` passed
[post-merge main CI](https://github.com/appandflow/react-native-reserved-regions/actions/runs/35536295960).
The release-notes/metadata commit runs the repository checks again; require its
exact-commit CI to pass before tagging. A native build verifies compilation, not
device behavior.

Retained development captures establish these observations:

- **Android API 36 foldable emulator:** the inset provider reported a zero-width
  division at `x=401.6`, `y=0`, with height `758.6` and content visible, alongside
  a clipped cutout at `x=779.5`, `y=0`, size `24.2 × 23.8`. The provider measured
  `803.7 × 758.6`. This demonstrates simultaneous native division/cutout data and
  provider-relative clipping. Capture: `regions-android-fold-cutout-inset.png`.
- **Android full-screen comparison:** the provider measured `851.7 × 882.9` and
  reported the cutout at `x=803.7`, `y=0`, size `48 × 48`. No active division was
  listed in that capture. Capture: `regions-android-fold-cutout.png`.
- **iPhone Duo simulator, iOS 27.1 outer display:** native occlusions were reported
  at `x=399.7`, `y=29.3`, size `37 × 37`, and `x=382`, `y=0`, size `84 × 170`.
  Capture: `reserved-regions-duo-outer.png`. This confirms outer-display occlusion
  observations, not inner-display activation or a fold transition.

These are simulator observations from development, not physical-device or
all-posture validation. The captures were retained locally under `/private/tmp/`;
archive the relevant originals with release review. Physical foldables, multiple
hinges, and iOS Duo inner-display/fold-transition behavior remain unverified.

Both documentation sites are local builds at the time these notes are prepared.
No hosted documentation deployment or npm trusted-publisher configuration is
established by this file.

## Synchronous measurement validation

Native layout events request synchronous delivery. The example carries the
unmerged React Native event-beat fix from PR #58530 and compiles iOS RN core from
source; the patch is not included in the published library.

The [iOS report](../verification/synchronous-initial-regions-ios-2026-09-20.md)
records nonempty native occlusions on the first captured content frame and a
measured empty result in the content-box provider. The
[Android report](../verification/synchronous-initial-regions-android-2026-09-20.md)
records the original timing defect and its fix. Three final cold launches showed
Ready with native regions in the first captured content frame. Older WindowManager
extensions and changes outside React mounting can still arrive later; no universal
first-frame guarantee is made.
