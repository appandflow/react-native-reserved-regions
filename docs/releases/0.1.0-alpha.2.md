# react-native-reserved-regions 0.1.0-alpha.2

Display divisions and occlusions in your React Native view's coordinates.

```sh
npm install react-native-reserved-regions@0.1.0-alpha.2
```

Version `0.1.0-alpha.1` was not published to npm. This candidate fixes the local tarball path
in the publishing workflow; its native library code is unchanged.

## API and fixes

- `ReservedRegionsProvider` and `useReservedRegions()` report active regions in
  logical points relative to the provider. Zero-width/height divisions are preserved.
- New `useReservedRegionsReady()` distinguishes the initial pending state from a
  completed measurement, including an empty result. Readiness stays true for
  that provider's lifetime.
- The tagged union distinguishes `division` with `occludesContent` from
  `occlusion`. iOS divisions currently assume content remains visible.
- Typed UIKit queries use SDK and runtime guards. Android maps separating or
  fully occluding WindowManager folds to divisions and display cutouts to occlusions.
- Native events request synchronous delivery. Android initial measurement runs
  after Fabric mounting, before its event beat. Cutouts use their bounding
  rectangles rather than a full status-bar rectangle.

## Requirements and migration

React Native's New Architecture is required. The tested example uses
`0.88.0-rc.1`; broader compatibility is not established. iOS observation requires
both the iOS 27.1 SDK and runtime, plus a host app using the UIScene lifecycle.
Older SDKs compile out observation even on newer devices. Android requires
API 24+, API 28+ for cutouts, and WindowManager-compatible hardware for folds.

Upgrade from alpha.0 to use the readiness hook and delivery/cutout fixes. Install
iOS pods and rebuild the native app. Give the provider nonzero bounds while
waiting for readiness. The library reports geometry; it does not reposition
content or replace safe-area/keyboard insets. Hinge angles belong to the separate
[react-native-hinges](https://github.com/appandflow/react-native-hinges) package.

Android clips rectangles to provider bounds. iOS forwards UIKit frames without
an additional clipping pass; those frames can include interaction margins.

## Verification and limits

- [Android 16/API 36 emulator checks](https://github.com/appandflow/react-native-reserved-regions/blob/v0.1.0-alpha.2/docs/verification/synchronous-initial-regions-android-2026-09-20.md)
  covered simultaneous native fold/cutout data, full-screen/inset/content-box
  coordinates, zero-width divisions, and a measured empty result. Three final
  cold launches showed Ready with native regions in the first captured content
  frame. Fold and cutout inputs were emulator overrides, not physical hardware.
- [iOS 27.1 Duo simulator checks](https://github.com/appandflow/react-native-reserved-regions/blob/v0.1.0-alpha.2/docs/verification/synchronous-initial-regions-ios-2026-09-20.md)
  covered outer-display occlusions and a measured empty content-box result.
  The first captured content frame contained Ready and native occlusions.
  This example used a React Native event-beat patch; installing the library does
  not patch a consuming app's React Native installation.
- The preceding native candidate passed [CI](https://github.com/appandflow/react-native-reserved-regions/actions/runs/35552174215),
  including package and native build checks. Native builds establish compilation;
  the linked runtime reports describe their tested development builds, not a
  post-install test of the npm artifact.

Readiness means measurement completed, not hardware support or guaranteed
first-frame delivery. Older WindowManager extensions can await a callback, and
pre-draw updates outside React mounting can arrive in a later frame. Physical
foldables, multiple hinges/windows, and Duo inner-display/fold transitions remain
unverified.

The repository example compares provider bounds with safe-area insets and region
overlays. Docusaurus source remains a local build; no hosted deployment is claimed.
