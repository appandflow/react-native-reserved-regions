# react-native-reserved-regions 0.2.0

Region frames are no longer clipped on Android, later region updates are regular
events on both platforms, and several Android measurement bugs are fixed.

## Breaking changes

- **Android frames are no longer clipped to the provider.** A region that
  intersects the provider is reported with its full frame, matching iOS. Frames
  can have a negative `x`/`y` or extend past the provider. Regions that don't
  intersect the provider are still omitted. See
  [coordinate spaces](https://appandflow.github.io/react-native-reserved-regions/docs/coordinates)
  for a helper that keeps only the visible part.
- **Only the first measurement is synchronous.** On both platforms the first
  measurement after a provider mounts is still delivered synchronously, so
  `ReservedRegionsGate` content mounts with it. Later changes are regular events
  that React receives at a later event beat, and pending changes are usually
  coalesced.
- **Android no longer re-measures on every frame.** It measures on the provider's
  own layout, fold changes and window inset changes. Scrolling, moving an ancestor
  or transforming the provider does not trigger a measurement on either platform.

## New

- `ReservedRegionsProvider` accepts a `ref` to the native view.
- On Android the provider now supports the same props as `View`, including
  `overflow`, borders and `borderRadius`.
- iOS re-measures when the provider moves without changing size.

## Fixes

- Android display cutouts use the provider's window position, so occlusions are
  correct when the window isn't at the screen origin, such as in split screen.
- Android no longer drops a region change when two happen in the same frame, which
  left the cutout at its previous position after a rotation.
- Android providers inside lists that clip subviews (`FlatList` on Android) no
  longer re-measure or re-send regions each time they scroll back into view.

## Migration

- If your code assumed frames were clipped to the provider on Android, intersect
  them with the provider size. Overlays drawn at region frames can now extend
  outside the provider; wrap them in a view with `overflow: 'hidden'`.
- If you relied on Android updating regions while a provider scrolls, measure the
  scroll offset yourself; regions describe the provider's position at its last
  layout.
- Reinstall pods and rebuild the native app.

React Native 0.80 or newer with the New Architecture is required. iOS
functionality requires the iOS 27.1 SDK and runtime. Same-frame delivery of the
first measurement on iOS requires
[react/react-native#58530](https://github.com/react/react-native/pull/58530),
which is not in React Native 0.88.

## Verification and limits

- React Native 0.80.3 builds and runs on iOS and Android; 0.79 fails at codegen.
- Android changes were verified on foldable (API 36) and phone (API 30) emulators
  with a display cutout overlay: rotations, fold postures, split screen, a paused
  app, and `FlatList` clipping. The Android end-to-end check passes in CI.
- iOS changes were verified on an iPhone 17 simulator (iOS 26.5) with a
  temporary stand-in region, because no iOS 27.1 runtime was available. Real
  UIKit reserved regions and iPhone Duo behavior were not re-verified for this
  release.
- Physical devices and WindowManager extensions older than 9 were not tested.
